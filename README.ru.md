# Конвертер ODT -> Diplodoc

Данный пакет скриптов автоматизирует превращение технической документации из формата ODT (LibreOffice Writer) в структуру, готовую для публикации с помощью **Diplodoc** — современного движка для технической документации.

Ниже кратко описано, от каких рутинных задач освобождается пользователь благодаря этому инструменту.

---

## 1. Разбивка одного ODT-файла на множество MD-файлов с сохранением иерархии

**Без инструмента:**  
Вручную открывать ODT, копировать каждую главу, создавать папки, вручную прописывать `index.md`, `index.yaml`, `toc.yaml`. При изменении структуры документа — переделывать всё заново.

**С инструментом:**  
Конвертер сам распознаёт заголовки (`#`, `##`, `###` …) и создаёт вложенные папки, в каждой из которых лежат `index.md`, `index.yaml`, `toc.yaml`. Структура полностью повторяет логику ODT.

---

## 2. Перенос изображений и исправление путей к ним

**Без инструмента:**  
Вручную извлекать все картинки из ODT, копировать их в нужные подпапки, вручную исправлять пути в Markdown-файлах (часто пути содержат абсолютные адреса с диском C:).

**С инструментом:**  
Скрипт запускает `pandoc` с параметром `--extract-media`, находит все изображения, копирует их в папку `media` рядом с каждым `index.md` и автоматически исправляет ссылки на относительные (`media/имя.png`).

---

## 3. Сохранение подписей к рисункам (в том числе номеров)

**Без инструмента:**  
Каждый раз вручную переписывать подпись под картинкой, проверять номер рисунка, соблюдать единый стиль («Рисунок 1. Название»).

**С инструментом:**  
Скрипт извлекает полную подпись из поля `{alt="..."}`, автоматически добавляет недостающий пробел после номера и выводит подпись курсивом сразу под изображением.

---

## 4. Превращение двухколоночных таблиц-заметок в блоки `{% note info %}`

**Без инструмента:**  
Вручную править HTML-таблицы, удалять лишние столбцы, переносить текст в теги `{% note %}`.

**С инструментом:**  
Конвертер находит таблицы вида `+-----+-----+ | ![](img) | Текст заметки | +-----+-----+`, удаляет левую колонку с картинкой, оставляет только текст и оборачивает его в `{% note info %}…{% endnote %}`.

---

## 5. Удаление мусорных атрибутов Pandoc (`{alt="..."}`)

**Без инструмента:**  
После конвертации Pandoc часто оставляет строки `{alt="Рисунок 49: …"}`, которые видны в финальном HTML. Приходится удалять их вручную в каждом файле.

**С инструментом:**  
Скрипт автоматически вычищает все подобные атрибуты, оставляя только чистый Markdown.

---

## 6. Генерация YAML-файлов, необходимых Diplodoc

**Без инструмента:**  
Вручную создавать `index.yaml` (с полями `title`, `href`, `meta`) и `toc.yaml` (с `items`, `include`).

**С инструментом:**  
Все YAML-файлы генерируются автоматически:  
- в каждой папке создаётся `index.yaml` и `toc.yaml`;  
- в корневой папке — `index.yaml`, `toc.yaml`, `index.md`;  
- ссылки в `toc.yaml` ведутся на `index.md`, а для вложенных разделов прописывается `include: {path: ..., mode: link}`.

---

## 7. Обработка внутренних ссылок (между главами)

**Без инструмента:**  
В ODT техпис часто ставит перекрёстные ссылки вида «см. главу 2». При конвертации они превращаются в `[см. главу 2](#anchor-209)`, которые в Diplodoc не работают. Приходится вручную вычислять пути и заменять ссылки.

**С инструментом:**  
Скрипт строит карту всех якорей (`anchor-209` -> `путь/к/разделу/index.md`) и автоматически заменяет ссылки на относительные пути, понятные Diplodoc.

---

## 8. Управление кэшем и опциями Pandoc через конфигурацию и CLI

**Без инструмента:**  
Приходится каждый раз заново перегонять ODT в Markdown, даже если меняется только постобработка (например, формат заметок). Невозможно передать Pandoc нужную строку формата (`markdown-raw_html+pipe_tables`).

**С инструментом:**  
- Можно сохранять кэш (папку с `full_doc.md`) и при повторных запусках не вызывать Pandoc — ускорение работы.  
- Через `cli.py` или датакласс `PandocOptions` задаются любые расширения формата (`+`, `-` или не указано).  
- Поддерживаются Lua-фильтры (например, для удаления атрибутов размера изображений).

---

## 9. Интеграция с Visual Studio Code

**Без инструмента:**  
Пользователь вынужден запускать скрипты из командной строки, запоминать пути и флаги, сложно отлаживать.

**С инструментом:**  
В репозитории поставляется файл `.vscode/launch.json` с настроенной конфигурацией отладки Python. Достаточно открыть папку проекта в VSCode, нажать `F5` — и конвертер запустится с выбранными параметрами.

Также расширение **Diplodoc** для VSCode (официальное) позволяет просматривать результат прямо в редакторе, проверять ссылки и YAML-структуру.

---

## 10. Гибкость для будущих доработок (архитектура стратегий)

**Без инструмента:**  
Любое изменение поведения конвертера требует правки основного кода, что рискованно и трудоёмко.

**С инструментом:**  
Вся постобработка вынесена в **стратегии**:
- Глобальные (применяются ко всему Markdown до парсинга).  
- Секционные (применяются к телу каждой статьи после парсинга).  

Добавить новое преобразование (например, превратить таблицы с тремя колонками в списки) — значит, создать один класс и зарегистрировать его в `__init__.py`. Остальной код не меняется.

---

## Как начать использовать

1. Установите Python 3.11+, Pandoc, PyYAML.  
2. Склонируйте репозиторий, создайте виртуальное окружение.  
3. Запусти `pip install -r requirements.txt`
4. Положите ваш `manual.odt` в корневую папку.  
5. Запустите `python cli.py manual.odt ./docs/ru --pandoc-format "markdown-raw_html"`.  
6. Результат готов для сборки через `diplodoc build`.

Подробнее о настройках — в комментариях к `cli.py` и в `config.py`.
